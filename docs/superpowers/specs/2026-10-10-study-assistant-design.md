## 1. 目标与非目标

### 1.1 目标

把目前跑在 DSH 对话里的「私人学习助手」变成一个**独立 Windows 桌面应用**，达成三件事：

1. **让现阶段（大二）的学习与生活计划变得明确**。用户当前以**学校课程**为绝对主线，考研推迟到大三再考虑、且可能取消。因此 App 的主语是「现阶段的学习与生活」，不是「考研备考」。
2. **App 与 AI 助手共用同一份数据**：App 直接读写 `学习与生活计划.md`，不产生第二套并行的计划数据。
3. **同时是一个可读、可改、可测的 Java 练习项目**：分层清晰、核心逻辑有单元测试、代码有中文注释说明取舍原因。

### 1.2 非目标（v1 明确不做）

| 不做的事 | 原因 |
|---|---|
| Android 端 | 用户明确搁置。但 `study-core` 保持纯 Java 零界面依赖，将来可整块复用 |
| **把考研写成主线或硬编码其科目** | 考研已转为「暂缓」目标，且可能取消。任何硬编码都会变成给一个可能不存在的目标搭的脚手架 |
| 统计图表（学习时长曲线、完成率环形图） | 档案中没有这些数据来源，硬做等于新增记录负担，违背「不加量」 |
| 每日打卡、提醒、通知、作业截止推送 | 原档案第 47 行写死「不给每天排时段表、不设每日打卡考核」，App 不能把它加回来 |
| 云同步 / 多设备同步 | 已选定「单文件导入导出」策略 |
| 真题 PDF 阅读器 | `study\真题\`、`study\答案\` 已有 PDF 阅读器可用，重复造无意义 |
| AI 直接修改文件 | 见 §3.3；AI 模块在架构上拿不到文件写入权 |
| AI function calling / 工具调用 / 自动 agent 循环 | v1 保持「AI 只出文本，人来拍板」，便于定位问题归属 |
| 本地模型推理 | 不在本期范围 |
| 情绪数据加密 | 见 §7.1 决策说明 |
| 用 AI 判断是否触发危机资源 | 见 §6.5；可靠性不足 |
| 否定语境排除（如「我不想自杀」） | 见 §6.5；宁误报不漏报 |
| 通用「作业管理器」（多课程待办、优先级算法、日历视图） | 现阶段只需清楚看到「每门课本周要做什么」，做重了就是换个方式制造压迫感 |

### 3.3 依赖方向（关键约束的落地）

依赖是**单向**的：

```
study-desktop  ──►  study-core
```

`study-core` 永远不知道界面的存在。这条约束承担两个职责：

1. **核心逻辑可无界面测试**：周界计算、目标状态规则、无损往返、迁移保真全部能在不启动 GUI 的情况下验证。
2. **AI 拿不到文件写入权**：`ai` 包**不依赖** `storage` 包。AI 客户端只能返回纯文本；写入必须由界面层拿到用户确认后，另行调用 `storage`。这不是靠提示词里叮嘱 AI「别乱改文件」，而是靠编译期就存在的依赖方向保证。

## 4. 数据层：无损往返

### 4.1 文件事实（已实测）

**迁移来源** `%USERPROFILE%\study\408-进度.md` 的实测值：

| 项 | 实测值 |
|---|---|
| 大小 | 13377 字节 |
| 编码 | UTF-8，**无 BOM**（严格 UTF-8 校验通过） |
| 换行 | **全部 LF**，0 个 CRLF，177 个 LF |
| 结尾 | 有换行符，末字节 `0A` |
| 行数 | 177 行 |

**这套编码约定同时是新建文件（`学习与生活计划.md`、`生活与情绪记录.md`）的写入约定。**

因此 App 读写必须固定使用 **UTF-8（无 BOM）+ `\n`**，不得使用平台默认编码，也不得做换行符转换。

**git 层面的配套**：仓库设 `core.autocrlf=false` 并用 `.gitattributes` 强制所有文本文件为 LF。否则 git 在 Windows 上会把检出文件转成 CRLF，测试样例在任何机器上一检出就与期望字节不符，`RoundTripTest` 必然失败。

**关于 CRLF / BOM 的处理（读取时保真，绝不静默转换）**：上面实测的是文件现状。若用户用别的编辑器改过文件，可能引入 CRLF 或 BOM。规则如下：

- **读取不崩溃**，把 BOM 与 CRLF 视为原文的一部分。
- **性质 P1 对所有合法 UTF-8 输入成立**：不修改就写回，字节完全一致——即**不自动转换换行符、不自动去除 BOM**。
- **非法 UTF-8 一律拒绝，绝不静默替换**：`read` 必须用**严格解码**（`CharsetDecoder` + `CodingErrorAction.REPORT`），遇到非法字节序列**抛出明确的领域异常**（消息含文件路径与首个非法字节的偏移），**绝不返回被 U+FFFD 替换过的字符串**。理由：`new String(bytes, UTF_8)` 会把非法字节静默换成 U+FFFD，一旦写回就**改变并毁坏用户文件**；中文 Windows 上 GBK 编码的文件很常见，这是本项目最危险的一条数据破坏路径。App 捕获该异常后，告知用户「该文件不是合法 UTF-8」并**不写入任何内容**。
- **新建文件**固定使用 UTF-8 无 BOM + LF。
- App 打开此类文件时给出**中性提示**（「该文件使用了 CRLF / BOM，与约定不符」），并提供**显式**的「规范化为 LF（无 BOM）」操作。**不自动执行**——自动转换会破坏 P1 并静默改写用户的文件。

### 4.2 块模型

文档解析为一个有序的「块」列表。块分两类：

| 类型 | 包含 | 界面 | 回写 |
|---|---|---|---|
| **结构块** | 表格类内容（见 §4.4 清单） | 类型化表单编辑 | 该块按统一列宽重新生成 |
| **原样块** | 标题、散文、有序/无序列表、引用块、HTML 注释 | 文本框直接编辑原文 | 未修改则**逐字节输出原文** |

每个块携带一个「脏」标记。

### 4.3 脏标记与回写

回写规则：

- 脏的结构块 → 重新生成
- 未脏的结构块 → 输出原文
- 未脏的原样块 → 输出原文（逐字节）
- 脏的原样块 → 输出编辑后的文本

**由此得到两条可断言的性质**，它们由单元测试直接守住：

| 性质 | 断言 |
|---|---|
| **P1 无损往返** | 解析后不做任何修改并写回，输出与输入**字节完全相同** |
| **P2 局部隔离** | 只修改一个字段，则**只有该块的内容变化**，其余块字节不变 |

**已知代价（明确接受）**：结构块一旦被修改，**整张表格**会按统一列宽重新排版（对齐空格变化）。表格是生成物而非手写物，此代价可接受。影响范围限于该表格内部，不涉及任何文字内容的增删，原样块永不受影响。

### 4.5 备份与外部修改检测

因为**同一个文件会被三方改动**——AI 助手、App、以及用户本人的文本编辑器——写入路径必须防御：

1. **显式保存，不自动保存**。这是计划原件，自动保存会在用户尚未想清楚时落盘。
2. **保存前备份**至 `%USERPROFILE%\study\.backup\`，文件名格式 `<原文件名>.<yyyyMMdd-HHmmss>.bak`，**每个文件保留最近 10 份**，超出按时间删除最旧的。
3. **绝不静默覆盖**。打开文件时记录内容哈希；保存前重新计算并比对。若不一致（文件被外部改过，例如 AI 助手刚更新过），弹出选择：「重新载入」或「覆盖」，**不代用户决定**。

### 4.6 一次性迁移（`408-进度.md` → `学习与生活计划.md`）

迁移是**一次性的、不可逆感的操作**，因此按最保守的流程设计。

**触发条件**：`学习与生活计划.md` 不存在，而 `408-进度.md` 存在时，App 提供迁移向导。

**执行步骤（顺序固定）**：

1. **备份**：`408-进度.md` 复制到 `.backup\408-进度.md.<时间戳>.bak`，并额外保留一份不可变归档 `.archive\408-进度.md`。
2. **映射**（见下表）。
3. **展示完整 diff**：新旧文件并排，用户逐节确认。**此时尚未写入任何文件。**
4. 用户点「确认迁移」后才写入 `学习与生活计划.md`。
5. **原文件 `408-进度.md` 保留不动**（不删除、不改名、不移动）。用户自行决定何时归档。

**设计意图**：这个 App 服务的是一个**计划本身会变**的人——主域可能从课程转向考研、考研可能取消、目标可能新增（四级、保研、考证）。凡是将来可能要改的东西，现在就不能锁死。锁定字段省下的那点实现工作量，会以「用户改不了、只能重新建档」偿还。

**唯一不提供的**：不做字段级历史版本、不做「撤销到上一版」。留痕由 §5.7 的周记录与 §4.5 的备份承担。

### 5.2 目标与状态（核心模型）

一切计划挂在**目标**下。目标字段：

| 字段 | 说明 |
|---|---|
| 名称 | 自由文本，如「本学期学校课程」「生活与身心」「考研（408）」 |
| 状态 | **进行中 / 暂缓 / 已取消 / 已完成** |
| 优先级 | 数字，越小越优先；暂缓/已取消的目标不参与排序 |
| 时间窗 | 自由文本，如 `2026.9–2027.1` |
| 说明 | 一句话 |

**四态皆为中性状态**，界面不使用红色或「失败/落后/已放弃」措辞：

| 状态 | 语义 | 界面表现 |
|---|---|---|
| 进行中 | 当前在做 | 进入「本周该做什么」 |
| **暂缓** | 现在不排时间，将来可能启用 | **不进入「本周」、不计入底线**；历史完整保留；**一键可恢复为进行中** |
| 已取消 | 决定不做 | 归入「已结束」；不显示为失败；记录保留以备回顾 |
| 已完成 | 做完了 | 归入「已结束」 |

「暂缓」是本项目最重要的新增状态：它既不是删除也不是放弃，因为用户**可能大三重新捡起考研，也可能决定不考**，这两种都不应被 App 判成负面。

**初始三行**（迁移或建档时写入）：

| 目标 | 状态 | 优先级 | 时间窗 |
|---|---|---|---|
| 本学期学校课程 | 进行中 | 1 | 2026.9–2027.1 |
| 生活与身心 | 进行中 | 2 | 长期 |
| 考研（408） | **暂缓** | — | 大三再定 |

### 5.3 课程（现阶段主域）

| 字段 | 说明 |
|---|---|
| 课程 | 课程名 |
| 本周任务 | 自由文本，如「第 4 章作业」「实验报告」 |
| 截止 | 可选日期；**仅作展示，不触发提醒** |
| 状态 | 待填 / 进行中 / 已完成 / **待回报** |

本学期 6 门课：数据库、Java、线性代数、物理学、电路分析基础、马克思主义基本原理。

**课程清单的单源约定**：§一 的「本学期课程」行是**课程清单的唯一来源**；§三 的表格行**由该清单生成**（新增/删除课程只在 §一 操作，§三 随动）。这样避免同一份课程列表在两个表格里各写一份、随后互不一致。

**学期切换**：§一 的「当前学期」字段可随时修改（如 `大二上` → `大二下`）。课程表只保留**当前学期**，换学期时直接编辑或清空即可——历史课程无需保留，因为周记录（§九）里已留痕。

**明确不做**：作业提醒推送；逾期红标；完成率统计；优先级自动排序算法。现阶段只需清楚看到「每门课本周要做什么」（见 §1.2）。

### 5.4 每周底线（自定义）

- 条目字段：**目标** + 项 + 量 + 怎么安排 + 状态。
- **不硬编码任何科目**。默认条目由 AI 按当前阶段建议（§7.4 现阶段规划），用户确认后写入。
- 「量」采用**自由文本**（如「每周 ≥2 次」「7 天里 ≥5 天」「每周 2~4 小时」），**不做单位解析**。理由：原档案里「每周 2~4 小时，≥2 次，每次 ≥20 分钟」这种自然语言一旦强行结构化，会丢失语义并限制表达。
- 砍单顺序为**自由文本有序列表**，原样保留。
- 目标处于「暂缓」时，其底线条目**不计入本周检查**；显示方式遵循 §5.1 的「暂缓 / 已取消目标的显示方式」配置（默认折叠，可改为可见灰显或隐藏）。

### 5.5 阶段排期

- 表：阶段 / 时间窗 / 主攻 / 验收标准。
- 保留**行序**，界面支持上移/下移。
- 可归属于某个目标。考研暂缓时，其阶段排期显示为「暂缓中」，**不进入「本周」**。
- 无进行中阶段时，输出提示句「当前无进行中的阶段排期」，**不显示为空白或错误**（避免制造"缺了什么"的暗示）。

### 5.6 周界与周序号（已实测验证）

- **周界**：周一 – 周日。
- **锚点**：第 1 周 = `2026-09-14`（周一）– `2026-09-20`（周日）。
- **周序号公式**：

  ```
  周序号 = floor((该日所在周的周一 − 2026-09-14) / 7 天) + 1
  该日所在周的周一 = 该日 − ((dayOfWeek(该日) + 6) mod 7)
  ```

  其中 `dayOfWeek` 采用 **ISO-8601 编号：周一 = 1 … 周日 = 7**（即 Java `DayOfWeek.getValue()` 的返回值）。验算：周一 → `(1+6) mod 7 = 0`（原地，即自身）；周日 → `(7+6) mod 7 = 6`（回退 6 天，正确落到周一）。

- **实测核对**（与档案现有标注逐条一致）：

  | 日期 | 星期 | 周序号 | 周区间 |
  |---|---|---|---|
  | 2026-09-14 | 周一 | 1 | 09-14 .. 09-20 |
  | 2026-09-21 | 周一 | 2 | 09-21 .. 09-27 |
  | 2026-09-28 | 周一 | 3 | 09-28 .. 10-04 |
  | 2026-10-05 | 周一 | 4 | 10-05 .. 10-11 |
  | 2026-10-10 | 周六 | 4 | 10-05 .. 10-11 |

### 5.7 周记录追加

「追加新一周」的实现是**在 §九 末尾按锚点插入**新的 `### 标题` 与 bullet 模板，**追加为主，绝不覆盖历史周记录**。原 6 周历史在迁移中一字不改地保留。

### 5.8 中性呈现原则（硬约束的界面落地）

档案中的规则「按周不按天」「做不完不倒扣、不补做、不追责」「不制造压迫感」必须在界面上一一兑现：

1. **不使用红色告警**；不出现「已逾期」「连续断签 X 天」「落后进度」等文案。
2. 未完成状态一律显示为「**待回报**」，不显示为「未完成」。
3. 无数据 = 「**未回报**」，**不等于**「未完成」。
4. 全局仅三种中性状态色：**进行中 / 已完成 / 待回报**，**不存在「失败」色**。暂缓与已取消使用中性灰。
5. 目标被暂缓或取消时，界面**不做总结性评价**（不出现「已放弃」「未坚持」等措辞）。

## 6. 生活与情绪域

### 6.1 文件与格式

**独立文件**：`%USERPROFILE%\study\生活与情绪记录.md`，**不写入** `学习与生活计划.md`。

分离的理由：将来把计划文件交给 AI 助手或导出分享时，**不会连带暴露情绪记录**。

文件由 App 在首次进入「情绪」页时创建，格式如下（**最新在最上方**；此处与 `学习与生活计划.md` 的「周记录按时间正序追加」刻意不同，因为情绪记录的使用场景是「打开就看最近状态」）：

```markdown
# 生活与情绪记录

> 本文件由「学习助手」App 维护，只存放在本机。
> 记录默认不会被发送给任何 AI；每次分析前 App 都会先展示将要发送的原文。
> 最新记录在最上方。

---

## 2026-10-10（周六）

- 情绪：疲惫 ｜ 强度：3
- 睡眠：7 小时
- 运动：无
- 生活事件：下午电路分析实验拖到六点
- 备注：实验报告还没写，有点烦

## 2026-10-09（周五）

- 情绪：平静 ｜ 强度：2
```

- 头部引用块 = **原样块**。
- 每个日期条目 = **结构块**，字段：`日期`、`情绪`、`强度`、`睡眠`、`运动`、`生活事件`、`备注`。**字段为空则该行不输出**。
- 新条目插入位置：第一个 `## ` 之前。
- 分隔符使用全角 `｜`，与主计划文件现有用法保持一致。

### 6.2 记录形式：低摩擦优先

| 字段 | 输入方式 |
|---|---|
| 日期 | 自动取当天 |
| 情绪 | **点选**：平静 / 有劲 / 疲惫 / 烦躁 / 低落 / 焦虑 / 开心 / 麻木（选项列表存于配置，可增删） |
| 强度 | 1–5，**由用户自己打分** |
| 睡眠 / 运动 | 可选 |
| 生活事件 | 一句话，可选 |
| 备注 | 自由文本，可选 |

**坚持点选的理由**：打字门槛高就会漏记，漏记多了会自责，最后彻底不记。这与「不制造压迫感」是同一件事。

**明确不做**：不做「连续记录 X 天」streak；不做「你今天还没记录」提醒；不统计「记录完整度」。断记不补、不提示、不追责。

**澄清一处易混淆点**：档案中的「按周不按天」约束的是**计划与任务的量**，不是「不许每天记心情」。情绪记录天然按天，两者不冲突。

### 6.3 生活准则

- 生活准则位于主计划文件的 **§五**，**归属于「生活与身心」目标**。
- App 提供**逐行文本编辑**界面：每行一个文本框，可增行、删行、调序。**不做结构化解析**——保持原样块语义，往返绝对安全。
- 输入框提供模板提示（例：「每周运动 2 次」「12 点前睡」），但**不强制格式**。
- **只规划，不考核**：不做完成率、不做打卡、不做连续天数。「生活与身心」是优先级 2 的目标且**不用于补学习**，界面不得把它变成考核指标。

### 6.4 AI 分析：逐次确认

流程（每步都是硬要求）：

1. 用户选择时间窗：近 7 天 / 近 30 天 / 自定义区间。
2. App 显示「将发送 N 条记录」**以及完整原文预览**。
3. 用户点「发送并分析」——**在此之前不发生任何网络请求**。
4. 输出内容包含三部分：观察到的模式、可能的影响因素、2~3 条可执行的小建议。
5. 输出措辞约束见 §6.5。

**分析结果不写回情绪记录文件**（该文件只装用户自己的记录，保持纯净）。用户点「保存到资料」时，写入 `%USERPROFILE%\study\资料\心理-观察记录.md`，沿用已有的资料文件约定。

### 6.5 危机兜底

#### 触发机制

- **本地关键词匹配**，不依赖 AI 判断。
- 关键词表存放于 `study-core\src\main\resources\crisis-keywords.txt`，**可在不重新编译的情况下更新**。
- 匹配规则：大小写不敏感；中英文与常见变体均收录。
- **不做否定语境排除**。「我不想自杀」同样触发。
  - 理由：这符合「宁误报不漏报」的取向。误报的代价只是一个**中性面板**（见下），漏报的代价可能是生命。而且「我不想自杀」这句话本身往往也是求助信号。

#### 呈现方式（中性）

- 命中时显示一个**中性的资源面板**——**不是红色警报**、不是弹窗打断、不追问细节、不质问、不评判。
- 面板列出 §12 的全部渠道：五条内置默认（用户可增删改）+ 学校心理健康中心（若已填写）。
- 文案方向：「这里有一些可以直接打电话的渠道，它们比我更管用。」

#### 关键决定：不阻断 AI

命中危机词时，**AI 分析照常提供**，不锁定界面、不强制中断当前流程。

理由：一旦形成「我说了真话 App 就锁死」的体验，下次就会开始写假的。保护机制不能以让人闭嘴为代价。

#### 措辞约束（对 AI 输出的硬要求）

- **禁止诊断性标签**：不出现「抑郁」「焦虑症」「中度」「心理健康得分 XX 分」等表述。
- AI 输出一律呈现为「**观察到**」「**可能相关**」的措辞，**不呈现为「评估结果」**。
- 情绪强度由**用户自己打分**；App **不计算**任何「心理状态分数」——那是对精确度的伪造。

## 7. AI 模块

### 7.1 配置

| 项 | 内容 |
|---|---|
| 字段 | `base_url` / `api_key` / `model` |
| 存储 | `%APPDATA%\xiaoyiyuan-study\config.properties`（JDK 自带 `.properties`，无额外依赖） |
| 协议 | OpenAI 兼容 `POST {base_url}/v1/chat/completions` |
| `base_url` 规范化 | 先去除用户输入末尾的 `/`；**若已以 `/v1` 结尾则不再追加**，否则追加 `/v1`。例：`https://api.deepseek.com` → `https://api.deepseek.com/v1/chat/completions`；`https://x.com/v1` → `https://x.com/v1/chat/completions`（避免出现 `/v1/v1`） |
| 输出 | **流式**（SSE），避免等待时界面像死机 |
| 自检 | 提供「测试连接」按钮，发送最小请求验证配置 |
| 超时 | 可配置 |

**Key 明文存储，并在界面上明确告知它是明文。**

理由：不实现「假加密」。客户端加密的密钥同样要存在本机，给不了真实安全性，只会让用户误以为安全。如实告知风险，比制造安全假象更诚实。

### 7.2 提示词：外部文件 + 内置回退

| 角色 | 外部文件 | 内置回退 |
|---|---|---|
| 学习与生活规划师 | `%USERPROFILE%\study\提示词\学习与生活规划师.md` | `study-core\src\main\resources\prompts\` 下的同名文件 |
| 生活管理与心理分析顾问 | `%USERPROFILE%\study\提示词\生活与心理顾问.md` | 同上 |

- 文件不存在 → 使用内置默认值，App **不崩溃**，且在设置页提示当前在用默认值。
- 文件存在 → **优先使用文件内容**，修改后立即生效，**无需重新编译**。
- 理由：提示词本质是「内容」而非「逻辑」。用户想调措辞（例如觉得顾问太啰嗦）应当改文件即可。

**角色 1 的定位变更**：原为「备考规划师」，现为「**学习与生活规划师**」——服务对象是现阶段（大二）以学校课程为主线的学习者，长线目标（含考研）可能暂缓或取消，规划必须对该变化保持中立。

### 7.3 功能

| 功能 | 界面形态 |

| **B 滚动** | App 自动读取计划文件 → 询问「上周完成 + 卡在哪」→ 生成复盘 → 确认后追加周记录 |
| **C 资料查找** | App 生成搜索关键词与提问模板 → **用户贴回搜索结果** → AI 整理为可溯源文档 → 存至 `study\资料\` |

### 7.4 规划类输出的硬约束（写入角色 1 的提示词）

这些约束随提示词一起下发给模型，并且 UI 不提供绕过它们的捷径：

1. **不评价过去**。禁止「你太差」「没救了」等表述，只讲「从现状到目标的路径」。
2. **信息不足先指出缺口**，并分级（哪些缺了必须停下补齐、哪些可默认但要标注假设）。
3. **禁止空洞口号**。「多刷题」必须展开为：科目 → 资源 → 具体动作 → 验收标准。
4. **强度匹配可支配时间**。时间少时**主动给出「可舍弃项」**。
5. **每条计划必须可检验**（例：「能独立默写单链表增删查」）。
6. **不制造压迫感**。不指责、不加量、完不成不惩罚。
7. **资源可核实**。书名 / 课程 / 分数线 / 招生人数必须联网核实，不凭模型记忆。
8. **文件单源、不并列**。变更原地替换，不堆「修订版」。
9. **砍单顺序强制**。规划类产出必须含「可舍弃项」或「砍单顺序」。
10. **长期目标中立**。考研处于「暂缓」时，**不得**劝说用户继续或放弃；只呈现"如果启用/如果取消"两条路径的差别。

### 7.5 逐次确认与无写入权

- **逐次确认门**（`ai` 包内的一个显式接口）：调用方必须传入将要发送的完整请求内容，由界面展示并获得用户确认后，才能发起请求。
- **AI 无文件写入权**：`ai` 包不依赖 `storage` 包，AI 客户端只能返回纯文本。写入动作由界面层在用户点击确认后另行触发。
- **AI 输出不落盘**：AI 返回的内容不自动写入任何文件；必须经界面展示全文、用户点「写入」后才由 `storage` 落盘。

### 7.6 对话历史与失败处理

- 历史存 `%APPDATA%\xiaoyiyuan-study\conversations\<id>.json`，**不进入 `study\` 目录**（不污染数据目录，也避免历史被连带分享出去）。
- 用户可点「导出到资料」，导出为 markdown 存入 `study\资料\`。
- 失败处理：网络失败 / 超时 / 401 / 429 → 中性提示 + 重试按钮，**不丢失用户已输入的内容**；流式中断则保留已收到部分并标记「**回复不完整**」（不使用「未完成」，理由见 §8.2 禁用词）。

### 7.7 v1 不做

function calling、工具调用、自动 agent 循环、本地模型推理、AI 自主读写文件。

## 8. 界面

### 8.1 页面清单（单窗口 + 左侧导航，共 8 页）

生活准则**不单独开页**——它属于「总览」与「目标」。

**全字段可编辑（§5.1）适用于以上所有页面**：计划文件各节的内容在**对应页面就地可改**，不存在「只能建档时设定」的字段；全局配置项集中在设置页。

### 8.2 状态色与文案规则

遵循 §5.8。汇总为可检查的清单：

- 三种状态色：进行中 / 已完成 / 待回报。**无红色、无「失败」色。**暂缓与已取消用中性灰。
- 禁用词：`未完成`、`逾期`、`落后`、`断签`、`失败`、`警告`、`已放弃`、`未坚持`。
- 无数据文案固定为「待回报」或「未回报」。
- 对已暂缓/已取消的目标，界面**不做总结性评价**。

### 8.3 技术选择

| 项 | 选择 | 理由 |
|---|---|---|
| UI 构建方式 | **Java 代码 + CSS 样式表，不用 FXML** | 全部为 Java（符合「用 Java 编写」要求）；少一层 FXML/控制器的隐式绑定，问题好定位；本机未安装 Scene Builder |
| JSON | **Gson**（约 280KB） | 仅用于对话历史；配置使用 JDK 自带 `.properties` |
| 模块化 | **不写 `module-info.java`**，走 classpath + `javafx-maven-plugin` | JPMS 对新手是纯粹的门槛；插件会自动处理 JavaFX 的 module-path |
| JavaFX 版本 | **25**（与 JDK 25 匹配） | JavaFX 25 要求 JDK 25，版本对齐 |
| 中文字体 | 在 CSS 中**显式指定字体族**（微软雅黑等） | JavaFX 中文渲染不显式指定可能出方块，为已知问题 |
| 测试 | **JUnit 5**，仅加在 `study-core` | 界面层不写单元测试 |

## 9. 测试策略

全部位于 `study-core`，按重要性排序：

| # | 测试 | 断言 |
|---|---|---|
| 1 | `RoundTripTest` | 解析 `学习与生活计划.md` → 立即写回 → **字节完全相同**（性质 P1） |
| 2 | `PartialEditTest` | 只改一个字段 → **只有该块内容变化**，其余块字节不变（性质 P2） |
| 3 | `MigrationFidelityTest` | 迁移后，原文件所有**原样块文本行**逐行存在于新文件（性质 P3） |
| 4 | `MigrationSafetyTest` | 迁移前生成备份；迁移**不修改、不删除**原文件；未确认前不写入任何文件 |
| 5 | `WeekBoundaryTest` | §5.6 全部实测值逐条通过；跨月、跨年、闰年边界 |
| 6 | `GoalStateTest` | 四态转换；「暂缓」目标不进入「本周」、不计入底线检查；可恢复为进行中 |
| 7 | `ExternalModificationTest` | 文件被外部改过后保存 → 触发提示，**不得静默覆盖** |
| 8 | `CrisisKeywordTest` | 危机词命中；**「我不想自杀」也必须命中**，且以中性面板呈现（无红色、无诊断词） |
| 9 | `PromptFallbackTest` | 提示词文件被删 → 回退内置默认，App 不崩 |
| 10 | `EmotionFileTest` | 情绪文件往返无损；空字段不输出该行；新条目插入到第一个 `## ` 之前 |
| 11 | `BackupRotationTest` | 备份文件命名正确；超过 10 份时删除最旧的 |
| 12 | `EncodingTest` | 固定 UTF-8 无 BOM + `\n`；不随平台默认编码变化 |

**关于测试数据**：使用脱敏样例文件存放于 `study-core\src\test\resources\`，**绝不把真实计划档案提交进仓库**。

**开发纪律**：`RoundTripTest`、`MigrationFidelityTest` 必须常绿。它们跑不过就不允许改动界面代码——它们守的是用户的数据。

## 10. 打包与分发

使用 JDK 自带的 `jpackage`，分两步：

| 步骤 | 产物 | 前置条件 |
|---|---|---|
| 第一步 | **`app-image` 免安装目录**（双击 exe 即运行，可整目录复制到其他电脑） | **无**，JDK 自带即可 |
| 第二步（可选） | `.msi` 安装包 | 需额外安装 WiX Toolset，用户确认后再做 |

- **提前告知体积**：产物约 150–250MB（含完整运行时）。这是 JavaFX 桌面应用的正常体积，非异常。

## 11. 风险与已知局限

| # | 风险 | 应对 |
|---|---|---|
| 1 | **JavaFX 25 + JDK 25 在本机尚未实际运行过**。版本匹配理论上成立，但未验证 | 实施计划的**第一件事**是跑通最小 JavaFX 窗口，成功后才写业务代码 |
| 2 | 首次构建需联网下载约 50–80MB（JavaFX + JUnit + Gson） | 网络不稳时先只构建 `study-core`（依赖仅 JUnit + Gson），界面后加 |
| 3 | JavaFX 中文渲染可能出方块 | CSS 中显式指定字体族（§8.3） |
| 4 | **危机关键词匹配必然存在误报与漏报** | 作为已知局限写入文档；不假装它能替代专业判断。误报代价被中性面板压低 |
| 5 | AI 分析质量取决于用户所选模型 | 界面上**不做任何准确率承诺** |
| 6 | 结构块被修改会导致整张表格重新排版 | 已在 §4.3 明确代价并接受；原样块不受影响 |
| 7 | **迁移是重构用户真实文件的高风险操作** | 三重防护：先备份 + 保留不可变归档 + 原文件不动；迁移前展示完整 diff 供确认；`MigrationFidelityTest` 断言内容不丢失；`MigrationSafetyTest` 断言原文件未被修改 |
| 8 | **主域变更后，AI 助手（skill）与 App 的文件路径约定需同步** | 已确认由实现一并更新 skill 中的路径与阶段描述，避免 App 改名后助手失联 |
